# 准备任务前端接入

日期：2026-09-30。

主页面创建/再相遇切换至 preparations API。提交前保存 personId、随机重试键、submittedAt，不保存记忆或文件。断线/刷新恢复相同键；提交成功后轮询状态 URL，不每次重复写请求。completed 后读取并验证 prototype manifest，再进入场景；failed/cancelled 给明确返回入口。隐藏/删除后的结果不可播放。

等待达到 40 秒提示仍在准备；60 秒停止自动轮询并提供继续查看或稍后查看。继续查看开启下一次等待窗口但保持原请求键；这是用户查看预算，服务端任务不被虚报成功。每个请求 10 秒客户端超时，离开组件或暂停查看会取消网络请求，迟到的读取不更新页面。

本地恢复信息依赖 localStorage；不可用时服务器任务仍持久，但当前前端尚无服务器任务列表来恢复丢失的浏览器键。准备任务状态不包含上传耗时，不能作为完整首访速度指标。上传阶段及 SSE、全面分阶段账本仍未完成。

## 验证

- 40/60 秒边界与恢复元数据测试两项、现有 api 九项通过；构建通过。
- 本地真实浏览器提交合成记忆，观察“正在准备这次相遇”，随后进入对应回头等待相遇。
- 临时停止本地 API，再点击再相遇，页面显示连接失败且保留继续查看/稍后再看；点击稍后再看显示保留请求。API 恢复后刷新，页面恢复准备进度并进入相遇。这里覆盖提交前断线恢复，不冒称服务器已接收未知请求的网络故障模拟。
- 暂停查看截图早期文案“服务端任务保留”发现不准确，已修正为“准备请求已保留”，因为请求可能尚未到达服务器。
- 截图：preparation-completed.jpg、preparation-restored.jpg；preparation-paused.jpg 为文案修正前的历史失败恢复画面。

没有在实际浏览器等待满 40/60 秒；阈值验证来自测试，不作为真实手机延迟或超时数据。当前任务依旧生成 local_placeholder/prototype，正式准备发布门未通过。

## 服务端待处理任务恢复补充

新增 GET /v1/persons/:id/preparations，只返回当前人物最近的一条 queued 任务 ID 和创建时间，要求会话所有权，private/no-store，不返回重试键或资料内容。主页在缺失本地恢复信息时调用该接口，用 preparationId 直接查询原任务，不重新提交。已完成任务继续由现有历史列表恢复；当前不列出失败/取消任务，也不跨人物寻找待处理任务。

相关准备任务七项与恢复元数据两项共九项通过，构建通过。新增测试验证 queued 可发现、完成后不重复恢复、异用户 404、删除后 404。本轮没有浏览器清除存储后的实际操作，前端此分支仍需浏览器验证；会话 cookie 同时丢失时不会恢复匿名身份的私有资料。
