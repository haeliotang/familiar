# 服务健康检查

日期：2026-09-30。

## 接口

- GET /health/live：200，{"status":"alive"}。不访问数据库。
- GET /health/ready：必需业务表与关键列可查询时 200，{"status":"ready"}；数据库错误、未迁移或关键字段缺失时 503，{"status":"not_ready"}。
- 两者无需用户身份，Cache-Control: no-store。就绪 SQL 使用 LIMIT 0，不读取用户行，响应不含连接串、文件路径或异常详情。

## 部署使用

由本机反向代理或部署监控访问 API 端口；当前 API 绑定 127.0.0.1。用 live 判断进程能否响应，用 ready 决定是否接收业务流量。外部探针应设请求超时（建议 3 秒）和间隔（建议 10 秒），不要无间隔轮询。生产迁移由现有 db:migrate 执行。

ready 仅验证数据库查询与所列关键字段，尚不涵盖所有约束、写权限、磁盘空间、ffmpeg/heif-convert、本地模型、资产指纹或完整播放。因此 ready=200 不等于试用版验收完成。此接口没有取消底层挂起数据库查询；生产数据库连接与查询超时仍需在部署配置中确定。运行中的旧服务需重启后才提供新接口。

## 实测

server/health.test.ts 两项通过：模拟数据库错误时 live 200 / ready 503；实际 PGlite 未迁移时 503、迁移后 200、删除 review_state 列后再次 503。pnpm build 通过，仍有场景分包大于 500 kB 的既有警告。本轮未进行真实部署或回滚演练。
