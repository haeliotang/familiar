# HEIC 本地转换验证

2026-09-30。测试素材为本地生成的 256×192 纯色 PNG 经 macOS 系统工具编码的 HEIC，不含真实照片或私人资料。

上传意图接受 image/heic、image/heif；照片选择器增加对应格式与扩展名。浏览器未填 MIME 时，仅对照片的 HEIC/HEIF 扩展名补 MIME；服务端仍读取实际图片结构。

照片标准化先读取尺寸并限制 4000 万像素。HEIF 容器由 heif-convert 转成 PNG，再按已有管线处理为最长边 4096 的 JPEG，输出不保留 EXIF。转换使用素材私有目录内随机临时子目录，30 秒超时，保留 libheif 安全限制；成功或失败均清除临时目录。处理失败沿用 rejected 终态并清除原始和输出文件。多图片容器若转换工具不产生预期单张文件则拒绝，不宣称支持所有 HEIF 变体。

证据：HEIC API 回归先以 415 失败，接入后完成上传→转换→ready，检查 JPEG 256×192、无 EXIF、目录仅有最终 JPEG。空 MIME 回归先失败后通过。相关客户端与服务端测试共 18 项通过，构建通过。

运行要求：系统 PATH 需要 heif-convert（本机 libheif 1.23.2）以及现有 ffmpeg/ffprobe。本轮未安装新 npm 包。部署必须提供同等解码工具并重新验证；缺失工具会导致转换失败。32×24 极小系统编码图片曾触发解码器尺寸安全限制，未关闭该保护。

尚未验证真实 iPhone 图片、HDR/色彩保真、复杂方向元数据、多帧文件、跨平台部署、转换过程中删除竞态或本轮 PostgreSQL 集成测试。本结果仅证明合成单张 HEIC 的本地转换闭环。

## 解码工具不可用时保留上传

后续修复：heif-convert 启动报 ENOENT 时单独返回 503/photo_decoder_unavailable；保留原始上传及 uploaded 状态，不误判为损坏。临时目录仍由 finally 清除。前端显示“照片处理暂不可用，已保留上传文件，请稍后重试”。其他解码错误仍进入 422/rejected 清理分支。

回归先通过临时移除测试进程 PATH 中的解码工具复现 422，再修复为 503；检查私有目录仅有原始 upload，资料状态为 uploaded。恢复 PATH 后重试同一资产 complete，成功 ready，目录仅有 JPEG。客户端及服务端相关测试共 20 项通过，构建通过。

这是同一资产 API 重试验证；界面目前尚无直接对 uploaded 照片再次 complete 的按钮，需继续补上，不能把提示文字视为完整界面重试闭环。

## 已上传照片的界面重试

新增 PhotoReview，读取服务端照片状态，刷新恢复 uploaded 的重试按钮。重试仅 POST 同一资产 complete；成功后显示已处理及用已有资料进入相遇。上传提交后清除已选择文件，避免后续直接再提交造成重复上传。处理期间锁住提交、示例、历史和删除操作；存在待核对记忆录音时保留录音核对流程，暂不显示照片继续入口。

实际主应用验证：以暂缺解码器的本地服务上传 synthetic.heic，返回首页看到等待处理；刷新仍有重试按钮；缺工具时点击重试仍保留等待处理且显示具体错误；恢复正常服务后点击同一按钮变为已处理，照片列表仍只有一项；用已处理资料去看看成功打开新相遇，返回后已处理状态保留。当前会话已有合成记忆，此次继续采用原有修补线索，不能算照片特征抽取证据。
