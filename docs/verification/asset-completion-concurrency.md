# 同一资料并发处理验证

日期：2026-09-30。

## 复现

PGlite API 测试上传一张合成 JPEG，然后同时发送 8 个 complete 请求。修改前结果为一次 200、七次 404。多个处理任务共用输出路径，后完成的任务更新不到 uploaded 状态后会删除输出，破坏已完成记录对应的文件。

## 修复

每个 API 实例按 assetId 排队处理 complete 请求；等待结束后重新读取资料状态和人物删除状态。已完成的后续请求返回 ready，不再转换或删除文件。finally 释放队列，并移除无等待者的队列项。鉴权仍独立执行。

## 验证

- 修改后 server/index.test.ts 的原 16 项和新增照片并发项共 17 项通过。
- 扩展新增测试至照片和合成 Kokoro WAV 两种资料，两项均通过：每种 8 个并发请求全部 200，目录只保留对应标准文件，状态 ready。JPEG 可解码、音频文件包含 RIFF 头。
- pnpm build 通过；仍有场景分包大于 500 kB 的既有警告。

## 边界

队列仅覆盖同一 API 实例。多进程或多实例共享目录仍需要共享任务锁或持久化队列。未覆盖并发 PUT、崩溃恢复或完整生产部署。本轮未重启用户正在使用的本地服务；修改将在下次服务启动后生效。
