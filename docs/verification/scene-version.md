# 场景种子、版本与清单校验

2026-09-30。新 episode manifest 使用 schemaVersion 1.1，保存 32 位 seed、sceneVersion `procedural-path-v1`、plannerVersion `memory-cue-template-v1` 及完整清单 SHA-256。清单摘要排除自身 manifestHash 字段，对对象字段排序，对数组保持原顺序。该摘要用于内容一致性，不是签名或身份认证。

前端不再将所有服务端记录的种子替换为零。API 映射核对完整清单，保留真实种子与版本；无法校验的记录不播放。缺失/未知场景版本与无效种子明确拒绝，历史列表仍保留入口，不追补虚构的历史参数。示例固定种子 1。

场景 v1 使用明确的相机、颜色、场景分支与按种子确定的树位置。树的位置只有小范围变化，保持在路径外。同一版本与种子重算布局相同。程序实现必须保留；以后改变布局需新增版本实现。

## 验证

- 场景布局 2 项测试：相同种子一致、不同种子不同、路径外位置、未知/缺失版本与无效种子拒绝。
- 清单规范化 1 项测试：键顺序不影响内容，种子与场景版本变更影响内容。
- API 映射 2 项测试：服务端完整清单通过；修改种子或声音计划后失败；旧记录不编造种子、版本或指纹。
- API 9 项测试通过，新记录摘要与实际保存清单一致，同键重复请求保存的整个清单不变。
- 全套本地测试：63 passed，10 skipped；跳过的是未配置数据库的 PostgreSQL 容器测试，本轮没有新增该数据库证据。
- 生产构建通过，仍有场景文件超过 500 kB 提醒。
- 已重启本地 API。浏览器合成“合成场景版本测试：回头等我”生成庭院相遇，人物和声音准备成功。页面刷新后历史入口为 `2026/9/30 17:43:22 · 旧时庭院`，点击后同样成功。保留这条合成记录供后续开发复查。
