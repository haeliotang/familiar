# Unicode 记忆输入边界

2026-09-30。文档 2.3 要求最多 500 个 Unicode 字符。本轮按 Unicode 码点计数，与当前 Zod 4.6.5 的字符串长度检查一致；组合字符/ZWJ 序列可含多个码点，不宣称按视觉字形计数。

问题：本地 createEncounter 使用 UTF-16 slice(0,500)，499 个汉字后接一个 emoji 会把代理对截断；首页原生 maxLength=500、转写页面 text.length 也使补充平面字符提前达到限制。新增本地边界回归先失败并观察半个字符，现使用码点截取和计数，不拆代理对。

服务端实际检查已经接受 500 个 emoji、拒绝 501 个，因此未修改服务端校验。新增文字记忆和转写确认 API 回归保留这一约束，检查保存内容与输入一致。转写页面允许编辑超限文本，按去首尾空白后的码点数禁用确认；首页输入保留前 500 码点并显示计数。

相关测试 12 项通过：memory-text 2 项、encounter 4 项、transcriptions 6 项。构建通过。浏览器输入 501 个 emoji，最终 DOM 值为 500 码点、1000 UTF-16 单元，末字符完整，页面显示 500/500；截图 unicode-memory-limit.jpg。测试后清空未提交输入，没有写入真实用户内容。

边界：本轮没有 IME 真机或所有复杂字形的编辑体验验证；计数单位为码点。此处输入规格修复不证明资料抽取、个性化或邀请试用门槛完成。
