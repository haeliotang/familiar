# 本人录音本地信号观测基础

日期：2026-09-30。

新增 GET/POST /v1/assets/:id/audio-observations，仅处理当前会话所属、已归一化 ready 的 deceased_audio/deceased 资料。GET 返回已有观察或 null，POST 在本机读取标准 16kHz 单声道 WAV，保存来源 asset ID、标准音频 SHA-256 与 signal-window-v1 结构。不向供应商发送录音，不生成原声模仿。

算法按 20ms 帧计算 RMS，在最多 180 秒内选累计能量较高的连续最多 30 秒；RMS 累加限制在 0.1，避免单个尖峰无限支配选择。同分时保留较早窗口。窗口内 RMS<0.01 的连续至少 120ms 区间记录为 quietIntervals；阈值以上只称 activeEnergySec，不称有效语音时长。样本绝对值>=0.99 计入削波比例；低能量和削波状态用于诊断，不代表说话主体或声音自然度。

subjectAttribution 固定 unverified，speechRate/pitch 明确 null。连续噪声、音乐或合成音同样可能有可测能量，因此 measured 不代表识别到人声，更不是熟悉感或独特说话节奏。多人辨别、本人确认、真实语音活动检测、语速/音高估计和节奏迁移仍未实现。本观察尚未接入主页面或自动准备阶段，也不改变现有预设音色。

写入前重新锁定并校验人物未删除；删除立即阻断查询并清除数据库观察，清理源资产时有外键级联。查询不缓存，路径及原录音内容不返回。重复分析同字节产生相同观察。来源读取基于私有 ready 文件不可变约定；多实例文件变更与实际 PostgreSQL 竞态仍需专项验证。

验证：静音、40 秒长合成信号选最后 30 秒、绝对静音区间、削波、非标准/NaN/空/超长输入；实际上传 Kokoro 合成 WAV并本地归一化后分析、指纹绑定、重复分析、异用户 GET/POST 拒绝、删除后空表；模拟迟到分析在人物删除后返回 404且不写回。六项测试通过，构建与类型检查通过。原生产/本地运行服务本轮未重启；新表需迁移后使用。没有真实录音或真人质量验收。

## 接入自动准备

配置私有资产目录的准备 worker 现在自动处理当前人物最新的 ready 本人录音。它执行真实 audio_signal_observation 阶段，在同一人物锁与发布事务内保存观察。音频相关 manifest 使用 schemaVersion 1.3，包含 sourceAssetId、分析版本、标准音频指纹、最多 30 秒窗口、信号状态；没有核实主体，所以保留 subjectAttribution=unverified。

声音计划明确 standard_voice_without_transfer、cadenceEvidenceIds=[]。分析失败不伪造观察：记录 status=unavailable、degraded=true、audio_analysis_unavailable，并继续现有标准声音原型路径。缺少私有资产目录的处理器不执行分析；生产启动必须配置 ASSET_DIR 才能处理文件，尚需部署门核对。

十四项音频/准备测试与构建通过。实际归一化合成 WAV 经 worker 分析得到匹配指纹与阶段；模拟分析失败生成明确降级记录。随后补强测试，先删除单独 API 已生成的观察，证明自动 worker 会从空表创建记录。仅分析当前最新本人录音，不进行多主体归属或多份音频融合。媒体分析当前位于人物锁事务内，远程/长耗时模型阶段将需另行任务租约方案。

## 用户可见说明与重新检查

前端恢复 manifest 的 degraded/degradationReason 与信号状态。相遇页明确显示分析失败仍使用预设声音；短/低能量录音提示可换更清晰录音，削波提示可能失真，可测量也明确尚未确认主体或提取个人节奏。资料列表新增“检查本人录音”，使用既有文件重新分析，无需重复上传。

十三项前端/API辅助测试与构建通过。真实本地浏览器上传已有合成 general.wav，自动准备后看到短/安静录音说明；返回资料页点击检查本人录音得到同样说明，再打开历史相遇仍保留状态。初始文案“较安静”不准确（短录音也会命中不足阈值），已改为“较短或较安静”。截图 audio-observation-note.jpg 与 audio-observation-review.jpg。分析 unavailable 分支的 UI 字段恢复测试通过，尚未在浏览器真实触发 unavailable/削波，不能据此声称所有音频错误 UI 已验收。服务已更新，使用的全为合成资料。
