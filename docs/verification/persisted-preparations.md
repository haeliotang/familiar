# 持久准备任务基础

日期：2026-09-30。

新增 `POST /v1/persons/:id/preparations`，要求匿名会话与 Idempotency-Key，返回 202/preparationId/statusUrl。`GET /v1/preparations/:id` 返回 queued/completed/failed/cancelled、结果 episodeId、结构化错误、次数、处理耗时和编排版本。请求、人物版本及状态持久保存，跨人物键复用返回冲突，跨用户查询返回 404。删除人物立即失效状态访问并取消其任务。

API 启动时和每秒处理持久队列，一次最多十项。按人物、任务顺序加数据库锁；相遇生成与任务完成在同一事务中提交，数据库事务回滚后仍可恢复。使用共享 manifest 构造器保持现有同步路线版本规则。资料版本变化返回 source_changed，无有效资料返回 no_usable_evidence。可观察的内部失败最多重试一次，两次失败进入 failed；进程直接崩溃依靠事务回滚恢复。关闭时停止调度并等待当前批次结束。

当前任务只执行已有本地模板编排，产物仍是 prototype/local_placeholder。completed 表示此项任务完成，不是正式 ready 发布门。providerCostUsd=0 反映当前没有外部付费调用；computeCostUsd=null 明确本机计算成本尚未测量。记录 durationMs 是处理尝试耗时，不是排队、上传或完整首访时间。

前端仍使用已有同步创建接口，尚未切换；本轮不会改变正在使用的服务。下一步接入前端恢复和 40/60 秒等待交互，再扩展分析、声音、校验阶段与分阶段账本。

验证：第一轮准备任务五项、原 API 十九项、健康检查两项共 26 项通过，包括同键去重、排队后关闭/重新创建服务并完成、读取隔离、隐藏失效、空输入、资料改变、删除、提交异常回滚后恢复。随后新增“两次失败终态”覆盖并更新健康检查所需表。真实 PostgreSQL 多 worker 竞争、进程强杀、40 组输入和正式阶段状态机尚待验证。

最终验证：准备任务六项与健康检查两项共八项通过；新增测试的类型声明修正后 pnpm build 通过，保留既有场景分包警告。

## 真实 PostgreSQL 双 worker 验证

临时 PostgreSQL 17，回环端口 55432，无持久卷。同键双提交返回同一个任务；测试在候选任务读取后设置同步屏障，明确让两个处理器都读到同一 queued 任务再争用锁。两者完成后数据库恰有一条相遇、任务 completed、attempts=1，证明本测试确实覆盖重复领取而非顺序调用。异用户查询 404；删除后任务 cancelled/episode_id=null、相遇 revoked/manifest={}；后续两个处理器调用不恢复资料。

pnpm test:pg：34 项通过、0 跳过，2.71 秒。测试容器已停止并自动移除。该结果为两个函数 worker 使用独立真实数据库连接的竞争验证；没有进程强杀、网络断连或远程推理，不声称已通过正式 worker 故障全部门槛。
