# 相遇重试与人物绑定

日期：2026-09-30。

先以两个同会话人物复现问题：人物 B 使用人物 A 的重试键，接口返回 A 的相遇（200），违反请求的人物绑定。

修复先锁定并确认请求人物仍属当前会话且未删除，再读取重试记录；若记录属于另一个人物，返回 409/idempotency_conflict；已隐藏的相遇返回 404。唯一约束竞争后的读取也检查人物和撤销状态。原有相遇版本不被重写。客户端为冲突提供具体提示。

新增测试覆盖跨人物键冲突、合法原记录重试、隐藏后重试及人物删除后重试。此记录仅验证本地 PGlite；并发不同人物使用同键在真实 PostgreSQL 上的验证仍待补充。

执行结果：server/index.test.ts 19 项与 src/api.test.ts 9 项共 28 项通过；pnpm build 通过，场景包体积警告仍存在。本轮未重启现有本地服务。

## 真实 PostgreSQL 补充验证

本轮使用临时 postgres:17 容器，端口只绑定 127.0.0.1:55432，无持久卷。新增测试同时为同会话的两位人物使用同一随机重试键，断言结果恰为 201 与 409，失败响应只含 idempotency_conflict，数据库恰有一行且绑定成功人物。随后验证合法重试返回原 ID、隐藏后 404、删除后 404。

TEST_DATABASE_URL 指向该临时数据库执行 pnpm test:pg：33 项全部通过，0 跳过，耗时 2.72 秒。测试后停止容器，由 --rm 自动删除。该结果覆盖本轮跨人物创建竞争，不代表所有删除时序或生产环境已验收。
